# Paragon PR7-V: notes for Claude

This repository starts as a copy of **Paragon PR7-G** (the guitar processor, repo `ARYEZ/Paragon-X1`), full history included, at PR7-G **0.32.1**. It is to become **Paragon PR7-V**, the **vocal** processor. A third sibling, **Paragon PR7-B** (bass, repo `ARYEZ/Paragon-PR7-B`), started the same way.

Everything below describes how the project is built, tested and released, and how the owner likes to work.

## First: make it its own plugin (do this before anything else)

**Done in 0.1.0** (plugin code `Pr7v`). Kept as a record of what makes PR7-V separate from PR7-G.

Until these are done, PR7-V *is* PR7-G as far as a DAW is concerned. The two would replace each other and share rigs and settings.

## The project

- An AGPLv3 **JUCE VST3** plugin: a vocal multi-effects chain, drawn as a floor processor with an expression pedal. No amp or cabinet: PR7-G's NAM amp and IR loader (and the NAM, Eigen and AudioDSPTools dependencies) were removed in 0.3.0 at the owner's request. JUCE is the only dependency. No latency, except while HARMONY's CORRECT (TUNE VOICE) is on: then a fixed 40 ms, reported to the host (the owner's choice).
  - Three finishes in SETTINGS → FINISH: Pearl White, Pearl White + Neon, Pearl Black (see `source/ui/Finish.h`).
- **The chain:** INPUT → LOW CUT → PITCH → (WAH pedal) → DYNAMICS (comp/gate) → DE-ESSER → FILTER/PITCH → GLITCH (Pre) → SATURATION (drive) → PRESENCE → TALK BOX → GRAPHIC EQ → GLITCH (Post) → HARMONY → DOUBLER → MOD → DELAY → REVERB → LO-FI → OUTPUT (+ volume pedal) → LIMITER. Mono up to the EQ, stereo from the DOUBLER on. LOW CUT (under INPUT) and LIMITER (under OUTPUT) are global like INPUT and OUTPUT.
- **The seven stomps** (the owner's order): top row **1 DYNAMICS, 2 SATURATION, 3 DOUBLER**; bottom row **4 PITCH, 5 MODULATION, 6 DELAY, 7 REVERB**. PITCH stays first in the *sound* (it tracks the clean voice best) though its stomp is 4; its stomp switches HARMONY, the octaver and TUNE VOICE (`harmonyCorrect`; since 0.21.1: TUNE VOICE works without HARMONY, so without this the stomp's light went out while the voice stayed tuned and 40 ms late, and PITCH seemed stuck on). `Footswitch` remembers each parameter's value (0-1), not just on/off, so TUNE VOICE comes back in its mode. FREEZE has its own switch. The DYNAMICS stomp switches the compressor and the de-esser (`compOn`, `deessOn`); the de-esser has its own DE-ESS block and panel in the strip (the DYNAMICS panel had no room). The other blocks (FILTER/PITCH, GLITCH, EQ, LO-FI) are in the signal-chain strip only. The display names are the owner's; parameter IDs keep their PR7-G names (`compOn`, `driveOn`...), as IDs never change.
- **Master LIMITER** (0.4.0): under OUTPUT, not a stomp; no look-ahead, so still no latency. Keep it that way.
- **De-esser** (0.5.0): split-band, after the compressor; FREQUENCY, AMOUNT, LISTEN (plays only what's removed).
- **HARMONY** (0.6.0, stage 1 of the owner's goal: "as close as we can get to Waves Harmony"; they sent its user guide). On the PITCH stomp (stomp memory: brings back what was on, first press HARMONY). `effects::Harmony`: PSOLA, formant-preserving; pitch read from the clean voice (after LOW CUT, a voice-range `PitchDetector`), voices made from the processed voice at the start of the stereo section. Key/scale (`Scales.h`, global like Waves' lock), 8 voices (`hv1Pitch`...), correction rule "a third stays a third" (our design), CORRECT FORMANT, SPREAD, SOURCE/HARMONY. `HarmonyPanel`: Waves-style graph. Voices lag ~2 pulses (8-25 ms); the dry voice has no latency (unless CORRECT is on, below).
  - **Stage 2, CORRECT** (0.17.0, `harmonyCorrect`, v38; shown as TUNE VOICE in the panel header): Off / Natural / Hard pitch correction of the singer's voice to the nearest key/scale note (Chromatic scale for any song), by the same PSOLA slices. Natural glides (60 ms), Hard jumps (3 ms); a note is held until another is 0.2 st nearer. Works with HARMONY off. The owner chose a fixed, host-reported delay: while on, the plugin runs `Harmony::correctLatencySeconds` (40 ms) late; the processor's timer calls `updateLatency()` (setLatencySamples from the message thread) and only then does the audio thread switch (`correctLatency`), so reported and actual always agree; voices then use the same fixed delay, in time with the voice. The guide's NOTES state is not built (needs Generate Notes / MIDI). Rigs: A08 Tuned Lead, E21 Hard Tune.
  - **Stage 3, GENERATE NOTES + CHORD maps** (0.19.0, v40: `harmonyGenerate`, `harmonyChord`, `harmonyMinNote`, `harmonyTolerance` (above 200 = Off), `harmonyToleranceTime`, `harmonyNoteLevel/Width/Formant/Attack/Release`; CORRECT gained "Notes"): `Harmony::generateNotes` holds a note until the voice is past TOLERANCE cents for TIME (silence ends it); the root goes into the key, then each `Harmony::chordMaps` interval through `Scales::harmonyNote`. 18 maps, ours (append only). Note voices: their own pool of 8 (Waves shares eight between fixed and note harmonies), exact notes (glide 30 ms), per-sample attack/release, panned by pitch across WIDTH. Panel: NOTES tab after 1-8; note voices drawn blue on the graph. Snapshot `PARAGON_SNAPSHOT_HARMONYNOTES=1`. Our choices: TIME in ms only (default 100 ms; Waves' default is a synced 1/2 note), TOLERANCE Off = only a silence starts a note. Not built: the per-key Note Map Editor, Spread/Fold, synced TIME. Rig E22 Auto Choir.
  - **Stage 4, MIDI notes** (0.20.0, `harmonyMidiMap` v41: As Played / Through Chord): `Harmony::MidiKeys` (velocity per key, sustain pedal) kept by the processor (`harmonyMidi`, read in processBlock beside MARS's MIDI). `generateNotes` gathers the wanted notes (MIDI keys first, then the generated chord, up to 8, deduped), keeps each voice on its note while still wanted, gives new notes the most-faded free voice, pans by pitch rank. Velocity gain 0.3 + 0.7v (ours). CORRECT Notes: the nearest held key in the nearest octave, else the generated note. Panel: MIDI dropdown in NOTES; keyboard strip C2-B5 on the graph (held pink, generated blue; `setMidiKeys`); graph 150 wide in NOTES. Snapshot `PARAGON_SNAPSHOT_MIDI=60,64,67`.
  - **Stage 5, the Note Map Editor** (0.21.0, v42): CHORD map 19 `Custom` (`Harmony::customChord`, the last: append only) and SCALE `Custom` (`Scales::Scale::custom`). The map: per note class a 47-bit mask (bit b = offset b-23, `mapSpan`/`mapBits`) in three 16-bit hidden parameters `harmonyMap{1-12}{A,B,C}` (`ParamIDs::harmonyMap (note, part)`), plus `harmonyMapFold` (Spread/Fold: Fold plays from `foldOctave` 60 + the note class). Keyed by the *sung semitone* (not put into the key first), so an out-of-key note has its own row; each mapped note then goes through `Scales::nearest`. FOLD moves a note an octave nearer while it's more than `maxShift` (24, the voices' 0.25-4 ratio clamp) from the sung note (our choice). Custom scale: `harmonyScaleNote1-12` (In/Up/Down, relative to KEY), global (`notInRigs`), `Scales::Custom` / `customNote`. The processor caches the parameter pointers (no string lookups on the audio thread). `NoteMapEditor` (ui/) is an overlay in `HarmonyPanel` opened by EDIT (`openNoteMap`: CHORD → Custom, copying the current built-in map in if the Custom map is empty); `fillFromChord` matches the engine exactly (a test checks every map, key and scale). Snapshot `PARAGON_SNAPSHOT_NOTEMAP=1` (with `PARAGON_SNAPSHOT_HARMONYNOTES=1`). Not built: per-note velocity/level, named saved maps.
  - **Stage 6, per-voice DELAY/FEEDBACK/FILTER and FLATTEN** (0.22.0, v43; the guide's Harmony Panel and Notes Panel): appended to `harmonyVoiceParts` ("Flatten", "Note" 24-72 default 48 = C3, "Delay" 0-1000 ms (0 Off), "Sync" `Delay::syncNames`, "Feedback", "Filter" `Harmony::filterNames` LP/HP/BP, "Cutoff" 20 Hz-20 kHz default 20 kHz); the note voices share `harmonyNoteDelay/Sync/Feedback/Filter/Cutoff`. `Harmony::Fx` per voice, `VoiceFx` per voice state: TPT state-variable filter (12 dB/oct, skipped when LP at 20 kHz or HP at 20 Hz), then a delay line (2 s, `maxEchoSeconds`; time glides ~30 ms; loop gain `feedbackAtFull` 0.97 x FEEDBACK), all before level/pan. The processor turns SYNC into ms (`harmonyFx`, `getTempoBpm`). Note voices keep running while their echo rings (`VoiceFx::ringing`); a fixed voice switched off clears its echo. FLATTEN in `readPitch`: NOTE (into the key with the voice's CORRECT) + FINE, PITCH ignored. Panel: FLATTEN switch (PITCH knob becomes NOTE), FX toggle after NOTES (`showFx`, `bindFxControls`, `updateVisibility`; picking a filter type that would silence moves CUTOFF), flattened markers show the note name; graph 196 wide in the voice view. Snapshot `PARAGON_SNAPSHOT_HARMONYFX=1`. Not the guide's: SYNC 1/64t-1 bar (ours is `Delay::syncNames`).
  - **Stages still to build, in order:** global glide/pitch/formant, snapshots, modulators. Call ours "inspired by"; never Waves' name or branding on the plugin.
- **Colours (0.21.2, from PR7-G 0.43.1/0.43.2, the PR7 family's look as on the PR7-E):** each signal-chain block and its edit panel take `ParagonColours::chainColour (block, numBlocks)` (red #e0103c → hot pink #ff2f7a → orange #ff7a1a along the chain, in `MainView::Block` order). Custom panels take it through `setAccent` (GraphicEqPanel, HarmonyPanel, DoublerPanel, MarsPanel). Exceptions on purpose: HARMONY's note voices stay blue, MARS's bands keep their colours, knobs and buttons stay `ParagonColours::accent` orange. A new block goes into the enum, the strip and `headers[]` in the same order.
- **FACEPLATE** (0.23.0, the owner's idea): `Faceplate` (ui/) at `mock (12, 568, 652, 822)`, where RIG BROWSER and SELECTED RIG were (removed with their classes: they only repeated the PRESETS page and the unit's display/SAVE). `MainView::selectBlock` calls `setBlock` (Unit dynamics/saturation/other, title, icon, chain colour, on IDs, TYPE ID). Looks: Classic (rack + VU gain-reduction needle), Daybreak (sunrise pedal, LED ladder), Revival (curve from `CompGate::revivalCurveDb` + 2:1 gate + GAIN ceiling, faders, meter), MARS (a tube per band, glow from `getMarsBandDrive`), generic rack (icon, name, TYPE, ON lamp). Meters with ballistics in `updateMeters` (timer 30 Hz; the snapshot calls it 30 times so renders show live meters). Our own designs, never a maker's look. **Since 0.23.1 (the owner: "the chassis ... need to match the chassis of the PR7 ... anything that is new for the faceplates needs to be themed as part of the PR7 line"), a faceplate uses only the PR7's own parts:** `PedalBody::paintUnit` (the unit's chassis and face, shared with the main unit, `Shape` for size), `PedalBody::paintSection`, `LedDisplay::paintScreen`/`paintGlassOverlay` and `ledOrange` (screens and readouts; meters as tuner-style LED bars), `ParagonLookAndFeel::drawPedalKnob` (knob angle pi*(1.2 + 1.6 x position)), `drawSmallKey`/`drawKeyStripe`, `drawFader`, `drawNeonBar`, `drawStampedText` with `Finish::ink`, `Finish::printedRed`, the badge's bold italic for names; it follows `Finish::changes()`. New elements are drawn in those materials (MARS's tubes in LED light behind a screen), never in a new style. Stages planned with the owner: 1 done (layout, DYNAMICS, SATURATION); 2 done in 0.24.0 (DELAY: TYPE as name, repeats by FEEDBACK with DUAL rows and a light running at the delay time (wall clock, not audio), TIME in `LedDisplay::drawDigit` seven-segment or the sync name, FEEDBACK/MIX knobs; REVERB: TYPE as name, pre-delay/early/tail shape from `Reverb::decaySeconds` (SPRING ripple, REVERSE swell), DECAY seconds, SIZE/MIX knobs; PITCH: sung note and TUNE VOICE target, voices by pan/interval with flattened and note voices, HARMONY/OCTAVE/FREEZE keys); 3 the rest (MODULATION, FILTER / PITCH, DE-ESSER, GLITCH, DOUBLER, GRAPHIC EQ, LO-FI).
- **Code layout:** DSP in `source/dsp/effects/`, UI in `source/ui/`, parameters in `source/Parameters.*`, rigs in `source/rigs/`, tests in `tests/`.
- **Parameters:**
  - Saved by ID and choices by **index**: only ever *append* choices, never reorder.
  - New parameters get a new version hint number.
  - Migrations for changed defaults live in `setStateInformation` and `Rig::fromXml`.
- **Shared DSP pieces:** `BypassFade` and `TailWatch` (EffectUtils.h), `PitchShifter` (correlation-spliced, used by Whammy-Wah, Shimmer, PITCH and Glitch).

## Build, test, check

- **Build:** `cmake -B build && cmake --build build -j8`.
- **Tests (Catch2):** `xvfb-run -a build/tests/ParagonX1Tests`. All must pass. New features get tests that check what the feature really does to the sound (levels, frequencies, harmonics, pitch), not just that it runs.
- **macOS can differ:** CI tests on Apple Silicon with Apple clang. In 0.10.0 every delay test failed there only (Linux gcc/clang, Windows and the sanitizers were clean): the first channel's echo came out at 0 through a small per-sample lambda choosing -1/+1 (FLIP). Rewritten as a plain per-side gain array, it passed. Prefer plain arrays/values over lambdas in per-sample loops, and when CI fails on one platform only, add a test that records the values (CAPTURE) rather than guessing. 0.10.0 was never published; 0.11.0 carries it.
- **pluginval:** `xvfb-run -a <pluginval> --strictness-level 10 --validate-in-process "build/ParagonX1_artefacts/Release/VST3/<name>.vst3"`. Check its **exit code**, not just "SUCCESS". CI runs it too.
  - Known flake on Linux: about one run in five ends "SUCCESS" then a segfault (exit 139) while unloading. A backtrace (0.17.0) puts it in pluginval's own VST3 host run loop (`juce::RunLoop::Impl` / `Steinberg::Linux::IEventHandler` map), not our code, and 0.16.0 does the same. If it happens, run it again; a failure before "SUCCESS" is real.
- **Screenshots** for checking the UI, via `xvfb-run -a build/tests/ParagonX1Tests "[snapshot]"` with environment variables:
  - `PARAGON_SNAPSHOT` (output path), `PARAGON_SNAPSHOT_WIDTH` (e.g. 2560 for 2x).
  - `PARAGON_SNAPSHOT_BLOCK=n` (open block n's panel; 0 = PITCH, which opens on HARMONY), `PARAGON_SNAPSHOT_PITCHVIEW=octave` (PITCH's OCTAVE / FREEZE view), `PARAGON_SNAPSHOT_PARAMS=id=value,...` (harmony voices: `hv1Pitch`, `hv3Active`...).
  - `PARAGON_SNAPSHOT_EXPRESSION`, `PARAGON_SNAPSHOT_PAGE=presets|settings`, `PARAGON_SNAPSHOT_PANELPAGE=n` (a paged panel's page: DELAY 0 MAIN, 1 STEREO, 2 COLOUR; REVERB 0 MAIN, 1 DECAY, 2 SPACE, 3 MOTION).
  - HARMONY's NOTES tab: `PARAGON_SNAPSHOT_HARMONYNOTES=1`, its Note Map Editor `PARAGON_SNAPSHOT_NOTEMAP=1`, held MIDI keys `PARAGON_SNAPSHOT_MIDI=60,64,67`, the FX view `PARAGON_SNAPSHOT_HARMONYFX=1`.
  - `PARAGON_SNAPSHOT_FINISH=black|neon`, `PARAGON_SNAPSHOT_LOUD=1` (a note over full scale: the LIMITER light on), `PARAGON_SNAPSHOT_PLAY=seconds` (a sung note first).
  - MARS: `PARAGON_SNAPSHOT_BLOCK=4`, `PARAGON_SNAPSHOT_PANELPAGE=0-3` (BANDS, GLOBAL, MOD, SLOTS), `PARAGON_SNAPSHOT_MODTAB=n` (0 XLFO 1 ... 9 XY 2).
  - Render, look, crop and zoom before claiming a visual change is right.

## Releases

- Bump `project(ParagonX1 VERSION x.y.z)` in CMakeLists.txt and add a matching `## x.y.z` section at the top of CHANGELOG.md, then push.
- CI builds Windows, macOS and Linux and publishes a GitHub Release with the three zips, using that changelog section as the notes.
- After pushing, check the release published (all three zips) about 15 minutes later, **and that its tag points at your commit**: CI skips publishing a version that already exists, so if another session released the same number first, yours silently isn't published (0.18.0: AEON was released first; GENERATE NOTES went out as 0.19.0). Before bumping, fetch main and take the next number after anything released.
- The owner installs from GitHub Releases on **Windows** and works in **BeatMaker**.

## How the owner likes to work

- **Explain the why**, specifically: what was wrong, what changed, and the trade-offs. Plain language; the owner is a musician, not a DSP engineer.
- **Be honest about limits:**
  - Say when something is our design rather than a copy ("modelled on", "inspired by").
  - Say when a detail is a guess.
  - Say what can't be checked here (audio by ear).
  - Ask for source material, such as manuals, program charts or gear rundowns, rather than invent specifics.
- **No trademarked names or branding** on our models: "Daybreak" (compressor), "GLITCH", "Mars" (not Saturn); the old drive pedals were "Screamer (TS)", "Muff Fuzz", "Face Fuzz". "Inspired by" in descriptions is fine. For vocals that includes pitch-correction and harmony products.
- **Show it:** send a rendered screenshot of any visual change.
- **"merge it"** means: open a PR from the working branch to main and merge it, then reset the working branch to the new main.
- Commit messages explain what and why.

## Ideas for the vocal version (to plan with the owner)

- **The input:** a microphone, not a guitar.
  - Done in 0.2.0: **LOW CUT**, a high-pass filter first in the chain (rumble and plosives), under INPUT.
  - The guitar tuner becomes a pitch display, or goes.
- **Vocal staples:**
  - **Pitch correction:** key and scale, speed from natural to hard "robot" correction.
  - **Harmony:** stage 1 done in 0.6.0 (see above).
  - **De-esser:** done in 0.5.0.
  - **Doubler:** stomp 3 since 0.3.0; in 0.7.0 rebuilt as four voices inspired by Waves Doubler (the owner sent its user guide). `effects::Doubler`: per voice gain/pan/delay/feedback/octave/detune/depth/rate (`dv1Gain`...), DIRECT, OUTPUT, shelves on the voices, FB HIGH-PASS, MOD RESET; `DoublerPanel` is a table. Detune uses `PitchShifter`, whose own ~12.6 ms delay is the shortest DELAY. Not built: Waves' ALIGN, RANGE and graphs. The 0.3.0 RATE/DEPTH/MIX convert (`convertOldDoubler`, parameter version 30), close rather than identical.
    - 0.9.0 (the owner: "doesn't feel very strong"): **DRIFT** per voice (`dv1Drift`, v32, our addition): slow random timing (±6 ms, 0.7 s glides) and pitch (±6 cents) wander, seeded per voice. Moving timing bends pitch; cancelling that with the detune can't work (the shifter's own delay undoes the move), so the timing glides slowly instead. Stronger starting settings (-2 dB, ±9 cents, 18/31 ms, drift 50%); `keepDoublerAsSaved` keeps 0.7.0's for rigs/projects saved before version 32. Mono output sums voices at full gain.
  - **Formant shift:** "chipmunk" to "giant" without changing the pitch.
  - **Vocoder or robot** voice.
  - **Megaphone / telephone / radio** lo-fi voices (LO-FI is a start).
- **Already useful as they are:**
  - The Daybreak compressor and the gate.
  - **Revival** (0.8.0): the compressor's third TYPE, inspired by Waves Renaissance Vox (the owner sent its short user guide). GATE (soft 2:1 expander on the peaks), COMPRESSION (one fader: threshold 0 to -36 dB, ratio 1:1 to 4:1, make-up so 0 dBFS stays 0 dBFS), GAIN (no-look-ahead peak limiter ceiling). Gate → comp → limiter, in `CompGate::processRevival`; params `revivalGate`, `revivalCompression`, `revivalGain` (v31). Attack/release and the curve are our choices; the guide gives none.
  - The graphic EQ (bands may move up for voice).
  - Delay and reverb: slap, plate, hall and throws.
  - **Delay upgrade** (0.10.0), inspired by Waves H-Delay (the owner sent its user guide): on every type, DUAL (`delayTimeRight`/`delaySyncRight`), ping START, PHASE flips, FEEDBACK to 200% (tanh in the loop only above 100%), LOW/HIGH CUT (12 dB/oct, on what enters the line, Off at the ends), MOD (triangle, ±4 ms at 100%), ANALOG Off/1-4 (our own four: drive, asymmetry, darkening, hiss on the heard echo only), LO-FI (5.5 kHz two-pole + 12 bits), 3.5 s. All v33 and neutral by default. Not built: H-Delay's filter LINK and OUTPUT. `EffectPanel` gained pages (`Group::page`, `setPages`): DELAY's MAIN / STEREO / COLOUR. Snapshot: `PARAGON_SNAPSHOT_PANELPAGE=n`.
  - **Reverb upgrade** (0.11.0), inspired by the Lexicon LXP manual the owner sent: a CHAMBER type (appended) and, for the network types only (`Reverb::hasNetworkControls`: not Classic or Spring), v34 controls that all start neutral: DECAY (x the type/SIZE decay, kept a multiple so switching TYPE keeps each space's length; the stomp tooltip shows seconds), BASS RT + CROSSOVER (split feedback per line, exact pass-through at 1.0x), ROLLOFF (output two-pole), DIFFUSION (x the type's, clamped 0.9), EARLY/REVERB levels, SPREAD/SHAPE (8 taps, energy-normalised, bypassed at 0 ms), SPIN/WANDER (x the line modulation). TONE stays the loop's RT hi-cut. Panel pages MAIN / DECAY / SPACE / MOTION. Not built: LXP's Echo and Reflection editors, Tap Slope, the realtime display.
  - Mod: chorus and flanger.
  - **MARS** (0.13.0): SATURATION, inspired by FabFilter Saturn 2. Since 0.14.0 (the owner's request) it is the only saturation: the PR7-G pedal models (Classic, Screamer, Muff, Face) and `effects::Drive` are gone, `driveModel`/`driveGain`/`driveTone`/`driveLevel` are legacy IDs read only by `convertOldDrive` (parameter version 36: Screamer → 2 bands, clean below 720 Hz + Saturated Tube with a mid push; Muff → American Amp, mids scooped; Face → Broken Tube; Classic → Saturated Tube; DRIVE 0-10 → 0.15 + 0.07x, TONE → TREBLE ±10 dB, LEVEL → band LEVEL; untouched-and-off drives left alone). `driveOn` switches MARS. Originally (0.13.0) (the owner sent its manual; they named it Mars). 1-4 bands (Linkwitz-Riley crossovers 6/12/24/48 dB, lower bands all-pass compensated; flat when the bands are off), per band (`mb1Drive`...): ON, STYLE (21, in Saturn's families; every curve our own: the manual doesn't describe them), DRIVE (with level matching measured once from the styles themselves: `Mars::measuredLevels`), DYNAMICS (gate left / pumping comp right), FEEDBACK + FB FREQ (silent input stops it), BASS/MID/TREBLE/PRESENCE, MIX, LEVEL; global INPUT/OUTPUT/MIX, QUALITY Off 1x / Good 4x / Superb 8x (IIR, no latency), SLOPE. v35. `MarsPanel` (BANDS / GLOBAL pages; display: click, drag crossovers, drag drive, double-click split, right-click remove). Mono section, so no pan or M/S. Not built: solo/mute, linear phase. CPU: 4 heavy bands about 12% of a core at Good.
    - **Stage 2, modulation** (0.15.0, parameter version 37; Saturn 2's manual chapter): `effects::MarsModulation` (MarsModulation.h). Fixed sources: 2 XLFO (16 steps, `mmLfo1S3Value`...), 2 EG, 2 EF, 2 MIDI, 2 XY, the expression pedal; 16 slots (`mmSlot1Source/Target/Amount`). Sources and targets are numbered (append only); `targetRange` must match each target's parameter (a test checks). Runs at a 16-sample tick (~3 kHz) only when a slot is active: `Mars::setKnobs` (knobs glided ~20 ms, then moved), `runSegment`; otherwise one tick per block, as before. The processor keeps `MarsModulation::MidiState` (note starts used once per block). UI: `MarsModUi` (ModSlider: right-click menu, rings), `MarsSourcesView` (MOD page), `MarsSlotsView` (SLOTS). Snapshot: `PARAGON_SNAPSHOT_PANELPAGE=2|3`, `PARAGON_SNAPSHOT_MODTAB=n`, `PARAGON_SNAPSHOT_PLAY=seconds` (sing a note first so live parts show). Not built: XLFO Snap, renaming sources, external side-chain, drag-and-drop.
